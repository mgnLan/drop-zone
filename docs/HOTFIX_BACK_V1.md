# ГОРЯЧИЙ ФИКС «НАЗАД v1» — софтлок в подэкранах меню (критично, принято создателем)

Скрин: «Личные настройки» — нет кнопки «← Назад», ничего не кликается.
Софтлок: войти в подэкран можно, выйти нельзя (помогает только F5).

## Причина (коммит d42800e)
Фикс «пустой подложки по центру» перенёс контент подэкранов в `menu_panel`
(reparent в _menu_back_show, ~10091–10101). Фиксированная кнопка
«← Назад» создаётся в layer ДО ScrollContainer и панели (~9152–9209) —
Godot рисует и отдаёт клики более поздним сиблингам: подложка-панель
(полупрозрачная, StyleBox bg 0.82 + рамка) оказалась ПОВЕРХ кнопки.
Кнопка формально visible=true, но закрыта панелью и мертва для клика.
Панель дочерняя к cc внутри ScrollContainer → перекрывает область
кнопки «Назад» (лежит в пределах меню-слоя).

## Фикс (инвариант: «Назад» ВСЕГДА поверх и кликабельна)
1. В `_menu_back_show(on)` при on: поднимать кнопку над всеми сиблингами —
   `layer.move_child(backb, layer.get_child_count() - 1)` (layer — тот же,
   куда она добавлена ~9159). Аналогично для menu_logo.
2. Защита от регресса: любые НОВЫЕ полноэкранные подложки/оверлеи в
   menu_layer добавлять ТОЛЬКО до создания backb или с mouse_filter,
   не перекрывающим кнопку.
3. Подстраховка: Esc в меню = _show_menu_main (если уже на главном —
   ничего). Требование UX: ни один подэкран не должен зависеть от
   единственной точки выхода.
4. Клики по контенту панели: проверить через ?uitree (дамп уже есть,
   коммит d42800e), что ветка menu_panel → vb → кнопки получает input;
   если панель перехватывает (STOP по пустым областям — ок), у кнопок
   внутри vb всё должно работать.

## Проверка
- 914×570 и 1280×800: Отряд / Личные / Настройки / Магазин / Медцентр /
  Касса / Battle Pass — «← Назад» видна, кликается, возвращает в лобби;
  Esc тоже возвращает.
- Все кнопки и поля внутри подэкранов кликабельны (аватар-пресеты,
  город, покупки).
- Скрины, FIXLOG, заливка на ТЕСТ (прод не трогать).
